# 架构

项目是 React 19 + TypeScript + Vite 的静态本地图鉴，使用 Tailwind CSS 4 和 HeroUI 3。组合工作台可通过浏览器调用用户配置的 OpenAI 兼容图片编辑接口。三个分发索引在构建时提供上架条目与筛选字段，`data/catalog.json` 提供已有条目的详细档案；筛选、视角和配方状态由 React 在当前页面内管理，刷新后不保留。

`src/App.tsx` 负责筛选条件、搜索、各卡片视角和配方选择；`src/components/ReferenceCard.tsx` 展示单组视角，`src/components/DetailDialog.tsx` 展示详情、下载与质检说明，`src/components/Workbench.tsx` 负责组合提示词和选中素材的展示。`src/types.ts` 维护素材类型和公共视角名称。Vite 构建时复制 `assets/` 到 `dist/assets/`，供预览和静态部署读取；原始图库保留在项目根目录。

公开下载按服饰、头饰和姿势的三个 `data/*-images.json` 索引分发。图鉴目录与分发索引分别维护；最新数量、视角和下载方式见[图库首页](../README.md)。下文中的批次编号和数量记录当时的制作范围。

每个素材有稳定 `id`、`kind`、`era`、`gender`、可选 `season`（旧单季）或 `seasons`（多季建议）、`season_scope`（共享内衬不分季节）、`presentation`（纯服装展示）、`age`、`occasion`、`structure` 和选题线索链接 `inspiration_url`，以及描述、审核状态、已归档的生成提示词、正面原图 `image` 和对应角度的 `view_files`。发型支持按参考年龄筛选；详情只显示已有的可选信息，选题视频不是历史证据。视角文件均为实际独立 PNG，并非从单图动态裁剪。当前图组通过内置 imagegen 生成，旧批次使用 macOS sips 分割，本次补齐批次通过 `tools/crop_four_views.swift` 按左上角像素坐标裁切，来源与质检状态以目录记录为准。

组合器按姿势、服饰、发型配饰排列参考图。姿势和服饰必选，服装与内搭共用服饰位置；发型与头饰共用一个可选位置。选择带年龄的发型时将参考年龄写入提示词，儿童或少年发型搭配衣物时提醒检查年龄适配。年龄筛选支持五个细分阶段，并保留旧有的成年与中老年标签。点击生成后，工作台按图号发送所选原图和提示词，结果在浏览器内预览与下载。非通用时期或性别标签不一致时提示创意搭配，不能作为历史正确性判断。

图片、提示词和筛选项可通过更新目录扩展。新增视角必须指向实际存在的图像并记录质量状态；多视角一致性及历史准确性需人工检验。`tools/verify.py` 只验证文件与数据一致性，不证明图像质量或史实。旧版静态页面文件保留，开发服务器可从 `/legacy.html` 打开。

角色服饰方案由 `src/roles.ts` 维护角色分类、适用题材、性别造型及四季内外搭描述，`RoleExplorer` 根据选择即时组合文字方案并可追加到工作台；只有明确关联的素材编号有专门参考图。角色方案不自动生成图片；汉、唐、宋、元、明、清题材通过显式角色映射提供内衬、外衣与头饰候选；清题材已关联实际素材。所有角色、称谓和形制均为待考证的创作参考。

汉朝通过 `data/han-role-outfits.json` 提供共享衣型候选；汉末僧人采用披裹衣创作参考，方士／早期道教人物复用日常衣型；角色映射保留时代边界，不宣称历史制度已考证。

唐朝服装包含 84 组成人外衣、8 组儿童四季外衣、7 组共享内衬。儿童 C240–C247 使用纯服装图，标记 `age: "儿童"`，保留原有季节；其余精选服装删除活跃 `role` 专属绑定，保留男女 `gender`；外衣通过 `seasons` 筛选，内衬 `season_scope: "不分季节"` 在四季筛选中均匹配。详情及组合提示词共用季节显示逻辑。`occasion` 保留礼仪、官服、军旅与宗教用途边界。

`RoleExplorer` 对汉、唐、宋、元、明、清按适用外衣与内衬数统计（含受限通用款），提供按性别和季节浏览共享衣型的入口，避免生成旧矩阵缺项。`tools/next_role_task.cjs` 跳过汉、唐、宋、元、明、清，导入器分配 ID 时同时检查现存源图，避免复用归档编号。

`CostumeFamilyGallery` 使用季节筛选前的汉、唐、宋、元、明、清服装集合确定 `costume_family` 分类，在组内调用 `matchesSeason`，使季节切换保持相同分类与顺序。季节无匹配只显示暂无匹配，不自动列为待补，不生成占位素材，也不能加入组合。时期、男女、搜索及视角条件仍先于分组执行；内衬独立筛选。

头部素材仍使用 `kind: "head"`，通过 `head_type: "hairstyle" | "headwear"` 区分发型与独立冠帽盔巾。`era: "通用"` 配合 `applicable_eras` 控制可复用朝代，`applicable_ages` 使基础发式能在多个年龄筛选中出现；通用不表示各时期细节或民族均相同。图鉴支持类型与通用／特有范围筛选。`choiceSlot` 将目录类别映射到三个配方槽位，同组换选时替换已有选择；工作台检查受限通用款与衣服的时代冲突并提示佩戴空间。详情显示适用时期。

元朝专属 63 组（53 外衣、2 内衬、8 头部）、明朝专属 59 组（48 外衣、3 内衬、8 头部），另有明清共享 12 外衣与 1 道冠，全部为纯服装或无人物头饰，按独特结构共享；不采用角色矩阵补图。`data/yuan-role-outfits.json` 与 `data/ming-role-outfits.json` 各维护 38 角色、51 常规性别选项；`RoleExplorer` 按该映射生成文字与候选，`CuratedRoleReferences` 共用于宋、元、明，按季节过滤外衣，内衬跨季。儿童引用通用 I227/I228，适用唐、宋、元汉地与明；僧人不设人物头部图。元朝的蒙古与汉地衣冠在用途与映射备注中注明限制，没有新增自动兼容性判断。

姿势库现有 P001–P028 共 28 组，统一灰衣参考模型；`pose_category` 明确动作分类，`applicable_roles` 关联 `roleCatalog` 的角色名，`props` 描述接触参照道具。分类从现有姿势数据派生，搜索包含角色与道具；`RolePoseReferences` 在角色方案下显示可用姿势，通过既有详情打开单张视角并加入配方，跳转时清除旧动作分类。成年姿势与儿童 P020 分开匹配，不按四季重复。工作台提示只参考动作、构图与道具接触，不复制模型衣服；衣装与头饰仍独立。

## 五朝季节缺项补齐

`sync_roles.py` 从本批角色基线继承同用途季节候选并关联儿童内衬；`RoleExplorer` 使用 `matchesEra` 将适用通用内衬纳入下拉与统计。`report.py` 生成六朝总览并刷新宋元明清角色、季节表；`verify_completion.py` 校验 309 条既有记录的变更范围、新增素材和四季角色覆盖。内衬不分季节，头部与姿势不在本批生成范围。纯服装视觉检查与历史正确性分别记录。

## 当前覆盖验收与唐朝角色映射

`data/tang-role-outfits.json` 与汉宋元明同样维护 38 类角色、51 个常规性别选项，RoleExplorer 直接引用候选，唐朝不再使用泛化的角色文字代替素材映射。I227/I228 经结构复查扩展至唐代题材儿童内搭，保留实际生成 prompt 并另记 reuse_note。新增 C478–C480 一二品武官狮补常服，独立于文官禽纹与军旅甲衣分类。

## 清朝接入与明代狮补修正

`data/qing-role-outfits.json` 提供 39 类角色、52 个常规性别选项。清中晚期新增 52 组素材：37 外衣、4 内衬、11 头部，全部为四独立视角。12 组僧道衣装和 H081 提升为 `era: 通用`、`applicable_eras: [明, 清]`；保留原编号、路径和实际 prompt。清朝含通用款共 19 个男女衣型、76 个四季格，52 个角色性别选项的 208 个季节组合均有候选。

`RoleExplorer` 纳入清朝映射，按 `matchesEra` 统计可用外衣；`App` 纳入清朝筛选与固定衣型分类。清代夏冬冠显式标记 `seasons`，角色文字与 `CuratedRoleReferences` 对已标季节的头饰同步过滤，其他跨季发饰不变。儿童内外衣独立比例；成年男子辫发不映射僧道，清代儿童双髻仅映射汉地女童。品级、满汉背景及朝／吉／便服用途由明确备注约束，不新增自动历史判断。

`output/qing-completion/tasks.json` 保存 52 组实际生成与裁切记录，`visual-review.json` 保存分批源图与独立裁图复查，`reuse.json` 记录共享范围。C496 按实图改为坎肩叠穿；I230 修正右衽方向，C503–C506 修正补褂对襟。全库当前 455 组、1820 张独立图；六朝 114 个分类、456 个四季格无缺项，覆盖不代表穷尽历史服制。验证仍用 `verify:assets`、`verify:coverage`、`typecheck` 与 `build`。

服饰的离线校色由 `tools/refresh_garment_colors.swift` 处理，生成参数与逐图哈希记入 `output/color-refresh/`。每组使用相同用途参数处理源图组和四个独立视角，不重画、缩放或依赖 CSS 滤镜。`tools/verify_garment_colors.swift` 在替换前逐像素核对尺寸、透明度、色相方向和暗部；catalog 可选 `color_adjustment` 只记录后处理，不改原始 `prompt` 或角色映射。

影视参考修复记录位于 `output/tv-costume-review/`，11 组沿用原 ID 和路径。catalog 的 `visual_reference` 记录剧目、来源与借鉴范围；`prompt` 是当前实际编辑提示词，旧提示词与旧校色参数分别转入 `prompt_history`、`color_adjustment_history`。公开剧照只用于研究报告，不加入 catalog；生产构建仅复制原创 `assets/`。本地对照页展示旧正面小样、剧照及当前独立四视图。

## 衣型核对与季节验收

季节为适用标签，不要求衣型、角色或冠帽覆盖四季。`verify:coverage` 验证角色候选存在、身份／性别／时代／儿童比例、内衬跨季、四视角文件及季节标签合法性；季节无候选仅作信息输出，不使检查失败。独特衣型的结构覆盖和历史准确性须另行核对，不能从此检查推导“服制齐全”。`output/iconic-costume-audit/` 保存联网来源、候选编号和抽样目视结论；此目录是审查建议，不修改主 catalog 或代表已生图。

本地视觉验收通过 `tools/review_batch.py` 处理一组或多组审核决定；颜色、形制、纯服饰、四视图、同类差异与剧照来源分别记录。入库事务同时更新目录、角色映射、任务、图片哈希与报告。进程异常中断时，下次调用批处理入口会先恢复未提交事务。图库交互仍直接读取构建时的目录。使用示例见 README 的“批量视觉验收”。
